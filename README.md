# ehs-risk-sem

Structural equation modelling for occupational safety risk, implemented in numpy,
together with the simulation studies that show where the method breaks.

The package exists because a particular kind of formula circulates in practitioner
writing on safety analytics:

```
Risk = 0.45*UnsafeActs + 0.30*OperationalStress
 - 0.25*SystemCondition - 0.20*SafetyResponseCapability
```

usually described as a structural equation model with AI-constructed latent
variables. This repository takes that formula seriously enough to build the
estimator that would be needed to produce it, and then to test what such an
estimator can and cannot support. Most of the answer is negative.

Nothing here analyses real injury data. Every number this repository produces
comes from data generated by a model whose parameters are known in advance.

---

## Requirements

Python 3.9 or later, numpy, pandas. Nothing else. Developed and tested on
Python 3.9.6 with numpy 2.0.2 and pandas 2.3.3.

```
git clone <this repository>
cd ehs-risk-sem
python3 -m unittest discover -s tests -v     # 107 tests
python3 simulations/run_all.py --quick       # ~16 seconds
python3 simulations/run_all.py               # ~11.5 minutes, writes results/
```

`run_all.py` writes tables to `results/`, which is checked in so the output can
be read without running anything.

## Worked example

```python
import pandas as pd
from ehs_risk_sem import ModelSpec, fit

data = pd.read_csv("synthetic/survey_style.csv", comment="#")

spec = ModelSpec(
    latents={
        "UnsafeActs":               ["unsafeacts_1", "unsafeacts_2", "unsafeacts_3"],
        "OperationalStress":        ["operationalstress_1", "operationalstress_2", "operationalstress_3"],
        "SystemCondition":          ["systemcondition_1", "systemcondition_2", "systemcondition_3"],
        "SafetyResponseCapability": ["safetyresponsecapability_1", "safetyresponsecapability_2", "safetyresponsecapability_3"],
        "Risk":                     ["risk_1", "risk_2", "risk_3"],
    },
    paths={"Risk": ["UnsafeActs", "OperationalStress",
                    "SystemCondition", "SafetyResponseCapability"]},
)

print(fit(spec, data).summary())
```

That file was generated with paths of 0.45, 0.30, -0.25, -0.20 and n = 1,200.
The fitted model returns 0.439, 0.244, -0.216, -0.207, with CFI 0.995, RMSEA
0.017 and SRMR 0.022. The fit is excellent by every conventional cutoff. The
estimate of the second path is off by 0.056, and the two negative paths come
back in an order that a reader would not be able to distinguish from noise.
That gap between fit quality and parameter precision is the subject of this
repository.

## What is implemented

| Module | Contents |
| --- | --- |
| `linalg` | Correlation matrices, safe inversion, nearest positive-definite projection |
| `special` | Incomplete gamma, chi-square, noncentral chi-square, normal CDF/quantile. No scipy |
| `measurement` | Principal-axis factoring, congeneric blocks, omega, alpha, AVE, Fornell-Larcker, HTMT, factor score determinacy |
| `structural` | Path coefficients from the disattenuated latent correlation matrix, VIF, direct/indirect/total effects by path tracing |
| `model` | `ModelSpec`, `fit`, `bootstrap_paths`, model-implied covariance |
| `identification` | t-rule, indicator counts, scale setting, recursiveness, degrees of freedom |
| `fit_indices` | chi-square, CFI, TLI, RMSEA with confidence interval, SRMR, AIC, BIC |
| `diagnostics` | Mardia skew and kurtosis, VIF, Heywood cases, listwise deletion accounting |
| `power` | RMSEA power, coefficient precision, sample size to distinguish two coefficients |
| `calibration` | Brier score with Murphy decomposition, reliability tables, ECE, calibration intercept and slope, net benefit |
| `glm` | Logistic regression by IRLS with ridge, King-Zeng rare-event bias correction |
| `rare_events` | Base-rate arithmetic, PPV, alerts per true event, sample size for a rate |

### The estimator

Estimation is limited-information and proceeds in two steps, following the
sequence Anderson and Gerbing (1988) argue for: fit and inspect the measurement
model first, then the structural model.

1. Each latent gets a congeneric one-factor block, fitted by principal-axis
   factoring with iterated communalities on that block's correlation submatrix.
2. Latent correlations are estimated by disattenuating the observed composite
   correlations using composite reliability. If the resulting matrix is
   indefinite it is projected to the nearest positive-definite matrix and the
   repair is reported rather than hidden.
3. Structural paths are solved from the latent correlation matrix by regression.

This is not full-information maximum likelihood, and the code says so in the
summary output. The consequence is stated at the point of use: the chi-square is
evaluated at the two-step estimates rather than at the ML minimum, which makes it
an upper bound on the ML chi-square for the same model. Fit reported here is
therefore conservative rather than flattering.

## What SEM can and cannot establish about causation

This is the section the repository is for.

**It can estimate causal quantities, but only relative to an assumed graph.**
Bollen and Pearl (2013) are explicit that structural coefficients are causal
parameters. That is not the same as saying the data identify them. The
coefficients answer a causal question conditional on assumptions that the data
cannot check: that the arrows point the way you drew them, that no omitted
variable causes both ends of a path, and that the structural disturbance is
independent of the predictors. Every one of those is an input to the analysis,
not an output of it.

**Fit cannot support the direction of any arrow.** Study 3A generates data from
`X -> Y`, then fits `X -> Y` and `Y -> X`. The two models return identical
coefficients (0.4927), identical standard errors, and chi-square agreeing to
better than 1e-6, because they imply the same covariance matrix. This is the
equivalent-models result of MacCallum, Wegener, Uchino and Fabrigar (1993). Any
procedure that picks a direction by comparing fit is picking on nothing.

**Reverse causation fits.** Study 3B generates a world in which injuries degrade
safety climate, then fits the model the literature usually fits, climate
predicting injuries. It returns beta = -0.570 with SE 0.015, a z statistic of 38, CFI
0.9999, RMSEA 0.004, SRMR 0.007. Every conventional cutoff passes. The direction
is backwards. This is not a hypothetical arrangement: Beus, Payne, Bergman and
Arthur (2010) report that injuries predicted later safety climate more strongly
than climate predicted later injuries.

**An omitted common cause leaves no trace in the fit indices.** Study 3C
generates a confounder driving both a predictor and the outcome. With the
confounder in the model the coefficient is 0.173 against a generating direct
effect of 0.200. Omit it and the coefficient becomes 0.495, an error of 0.295,
while CFI is 1.000 and RMSEA is 0.000. Fit indices are computed from the
covariance matrix of the indicators in the model, so a variable you did not
measure cannot degrade them.

**Coefficients conditional on a mediator are not what readers think they are.**
Study 3D generates `X -> M -> Y` alongside `X -> Y`. The direct effect of X with
M in the model is 0.182; the total effect is 0.442. Both are correct estimates
of different quantities. A table listing four coefficients as comparable
contributions to risk, without saying which of the two each one is, cannot be
interpreted. Westreich and Greenland (2013) named this the Table 2 fallacy;
Cole and Hernán (2002) show the direct effect is generally biased for anything a
reader wants.

**A latent score is not a probability and does not identify a person.** The
model output has no link function, no exposure denominator and no time window,
so no threshold on it can be justified. Separately, factor scores are not
uniquely determined by a fitted model. The summary output reports factor score
determinacy and the Guttman bound for each latent: on the worked example above,
two equally valid sets of scores for the same factor can correlate as low as
0.54 to 0.59. Steiger (1979) and Grice (2001) are the references. A per-crew or
per-shift score inherits that indeterminacy no matter how well the model fits.

What follows is not that SEM is useless. It is that the causal content of a
fitted model comes entirely from the assumptions the analyst brings, and those
assumptions should be written down and defended rather than left implicit in an
arrow diagram. Hernán (2018) and Grosz, Rohrer and Thoemmes (2020) both argue
that hedging with the word "predicts" while reasoning causally is worse than
stating the causal claim and its conditions.

## What the simulation studies show

All four studies generate data from known models. Reproduce with
`python3 simulations/run_all.py`. Tables land in `results/`.

### Study 1: sample size

Three requirements that safety papers collapse into one, for the model above
(5 latents, 3 indicators each, df = 80):

| Requirement | N |
| --- | --- |
| 80% power for the test of close fit | 153 |
| SE = 0.05 on a single path | 369 |
| Distinguish 0.45 from 0.30 at 80% power | 770 |
| SE = 0.025 on a single path | 1,459 |
| Distinguish -0.25 from -0.20 at 80% power | 6,884 |

The first row is the one cell in this table that can be checked against a
published source. MacCallum, Browne and Sugawara (1996) print 154 for df = 80;
this package returns 153, because power at N = 153 is 0.8002 and 153 is
therefore the smallest integer attaining the target, while their interval-halving
search stops at an approximation. `tests/test_maccallum_1996_tables.py` pins all
257 cells of their Tables 2, 4 and 5 against the values printed in the article,
and this is the only cell where the two conventions disagree.

Global fit power is satisfied first and is almost never the binding constraint.
A study with N = 250 can pass the fit test, report the four coefficients, and
have no basis whatever for the claim that one of them is larger than another.
Separating -0.25 from -0.20 needs roughly 6,900 observations.

The estimator is close to unbiased throughout: the largest bias across the four
paths is 0.0074 at N = 100 and 0.0014 at N = 5,000. The analytic standard errors are not
adequate. They run 63% to 76% of the empirical standard deviation, and 95%
interval coverage sits between 0.76 and 0.86 without improving as N grows,
because the omitted term (uncertainty in the estimated latent correlation
matrix) does not shrink relative to the rest. The nonparametric bootstrap in
`bootstrap_paths()` restores coverage to 0.925-0.975 at N = 500. Use it. That
comparison rests on only 40 replications, because each one refits the model 199
times; the Monte Carlo error on a coverage estimate from 40 replications is
about 3.4 percentage points, which `results/study01_bootstrap.csv` reports in
its own column. The bootstrap being better than the analytic interval is clear
at that resolution. Whether it reaches exactly 0.95 is not.

### Study 2: rare events

At the 2024 US private-industry total recordable case rate of 2.3 per 100
full-time-equivalent workers:

- 1.15e-05 per worker-hour, 9.2e-05 per 8-hour shift
- one recordable per 10,870 worker-shifts
- at 80% sensitivity and 95% specificity: PPV 0.0015, or **680 alerts per true
  event**
- at 80% and 99%: 137 alerts per event. At 90% and 99.9%: 13
- estimating the shift-level base rate to ±10% needs about 384 events, which is
  4.18 million worker-shifts

Discrimination is close to useless as a decision criterion at these rates. Across
base rates from 0.30 down to 0.0005 -- a factor of 600 -- the AUC moves only
between 0.677 and 0.692, with no trend, while the Brier score falls from 0.190
to 0.00062, a factor of about 300. Almost all of that fall is its uncertainty
term, which is a property of the outcome rather than of the model. Neither
number tells an operations manager what fraction of alerts will be real.

The class-imbalance result is worth stating on its own. Undersampling,
oversampling and SMOTE-style interpolation were applied to the same training
data at a 0.005 base rate:

| Training sample | AUC | Mean predicted | Observed | Overprediction |
| --- | --- | --- | --- | --- |
| As collected | 0.711 | 0.0051 | 0.0052 | 0.98x |
| Random undersampling | 0.708 | 0.454 | 0.0052 | 88.0x |
| Random oversampling | 0.711 | 0.452 | 0.0052 | 87.6x |
| SMOTE-style | 0.711 | 0.448 | 0.0052 | 86.9x |

Ranking is unchanged; the reported probabilities are wrong by nearly two orders
of magnitude. This reproduces on generated data what van den Goorbergh et al.
(2022) and Carriero et al. (2025) established by simulation for clinical
prediction models. If a safety model applies any of these corrections and then
reports a risk number, that number is not a risk.

Study 2 also covers maximum-likelihood intercept bias at low base rates with the
King-Zeng correction, and zero-inflated counts, where a structural-zero fraction
of 0.38 raises the observed zero fraction to 0.52 against a Poisson expectation
of 0.24. Reported zeros mix "nothing happened" with "nothing was recorded", and
the counts alone cannot separate them.

### Study 3: misspecification

Five ways to be wrong while fitting well. Summarised in the causation section
above: equivalent models, reverse causation, omitted common cause, conditioning
on a mediator, and a formative construct fitted reflectively. In the last case
the disattenuation divides by a reliability of 0.14, the latent correlation comes
out at 1.06, the correlation matrix has to be repaired, and the structural
coefficient hits the boundary at 1.0 against a generating value of 0.4. Equipment
age, overdue preventive maintenance and alarm rate constitute system condition
rather than reflecting it, and they have no reason to correlate; Jarvis,
MacKenzie and Podsakoff (2003) document the bias from getting this backwards.

### Study 4: the coefficients themselves

Whether 0.45 / 0.30 / -0.25 / -0.20 look like estimates: across 1,000
replications, the sum of absolute estimated coefficients had a median of 1.19
with a 5th-95th percentile range of 0.99 to 1.41. The published vector sums to
exactly 1.20 and every element lands on a round twentieth. Estimates are
continuous, so the comparable event is landing within 0.005 of a twentieth: if
each coefficient's position within its 0.05 cell were uniform, the chance of
all four doing that is (0.01/0.05)^4 = 0.0016. It happened in 1 of the 1,000
replications. A vector of this shape
is better described as a chosen weighting than as an estimate. Publishing chosen
weights is legitimate; giving them standard errors is not.

Whether the coefficients identify a structure: three structurally different
generating worlds all return approximately the same fitted vector. In the first,
intervening on UnsafeActs has effect 0.45. In the second, SystemCondition also
acts through UnsafeActs, and its total effect is -0.070 rather than the -0.250
printed in the table. In the third, an unmeasured common cause makes the
intervention effect 0.281. The coefficients do not distinguish these worlds.

Applying standardized coefficients to raw inputs: standardized paths operate on
z-scores. The study takes two crews at two sites differing only in the standard
deviation of overtime. Scored on raw inputs the site is ignored entirely. Scored
on z-inputs the ranking of the same two crews reverses between sites. Only the
standard deviations differ, and only the standard deviations are needed to flip
the answer.

Measurement non-invariance: two sites where one loading differs (0.77 vs 0.30)
give composite reliabilities of 0.823 and 0.675. Imposing Site A's measurement
model on Site B moves 4.6% of units across the top-decile flag. A score of 3.2
does not mean the same thing at two sites unless invariance has been tested, and
it is rarely tested.

## Honest limitations of this repository

- **The estimator is limited-information, not ML.** Full-information ML would
  give a proper likelihood-ratio chi-square and asymptotic standard errors from
  the information matrix. The two-step approach was chosen for transparency and
  because it makes the measurement model inspectable before the structural model
  is interpreted, but a reviewer comparing against lavaan or Mplus will get
  slightly different chi-square values. The direction of the difference is
  stated in the summary output.
- **Analytic standard errors are known to be too narrow** and Study 1 quantifies
  the shortfall. The bootstrap is the supported path. This is a real limitation,
  not a caveat that can be read past.
- **Only recursive models with congeneric measurement blocks** are supported.
  No reciprocal paths, no cross-loadings, no correlated residuals, no
  multi-group estimation, no missing-data handling beyond listwise deletion
  (which is counted and reported).
- **Ordinal indicators are treated as continuous.** Likert items are not
  interval, and a polychoric correlation approach would be the correct
  treatment. This is not implemented.
- **No empirical validation.** Nothing here has been fitted to real injury data.
  Recovery of a parameter from data generated by the same model checks the
  estimator, not the model, and certainly not any claim about workplace safety.
- **One real-world constant, and it is the only one.** The 2.3 per 100 FTE
  total recordable case rate is verified against the primary BLS source and
  cited at its definition in `rare_events.py`. Every function takes the rate as
  an argument, so a different industry, year or establishment rate substitutes
  freely and nothing in the package depends on the constant.

## Data

`synthetic/` holds three generated datasets. Each CSV opens with `#`-prefixed
lines stating that the file is synthetic, naming the generating model and its
parameters, and giving the seed and generation date. Read them with
`pandas.read_csv(path, comment="#")` and regenerate with
`python3 synthetic/generate_synthetic_datasets.py`.

Simulation studies are standard methodology for evaluating an estimator, and
that is the only use generated data has here. No number computed from these
files is presented as a finding about workplace injuries. Real empirical work on
injury data belongs to OSHA Injury Tracking Application filings, BLS Survey of
Occupational Injuries and Illnesses estimates, and MSHA accident records, none
of which this repository analyses.

## Environment note

On macOS with numpy 2.0.2 built against the Accelerate BLAS, `matmul` emits
spurious `divide by zero`, `overflow` and `invalid value` RuntimeWarnings on
products of finite matrices that produce finite, correct results. Confirmed on
this machine with two random matrices. `ehs_risk_sem/compat.py` provides a
filter matching only those four exact messages, called explicitly by the
simulation runners and by nothing else. Floating-point warnings are not
suppressed anywhere else in the package.
